## 排查 lumos-main `docker compose up -d` 失败（mysql unhealthy）
- 根因 1（已修复）：早前为复现 MySQL 初始化错误，用 `docker run --rm` 起了 `lumos-mysql-diag` 挂载同一个 `lumos-main_mysql_data` 卷，被 timeout 杀掉后 `--rm` 未清理，容器残留并持续占用数据卷，导致 compose 的 `lumos-mysql` 启动异常/不健康。移除该残留容器 + `docker restart lumos-mysql` 后，MySQL 健康（8.0.46，InnoDB 正常）。
- 根因 2（镜像陈腐，待重建）：`lumos-backend` 启动即 `ImportError: email-validator is not installed`。`backend/pyproject.toml` 已声明 `email-validator>=2.0.0`（Auth 区），但本地 `lumos-main-backend` 镜像构建于 14:05:59、不含该包 → 镜像是在该依赖加入前构建的陈旧镜像。修复：`docker compose up -d --build backend`（或 `docker build --no-cache -t lumos-main-backend -f backend/Dockerfile backend/`）。
- 环境坑：本机 Bash 里的 `docker.exe` 连的是 `dockerDesktopLinuxEngine` 管道，会间歇性断开（"failed to connect to the docker API"）；PowerShell 里的同一 `docker.exe` 才能正常跑 `docker compose`。Docker Desktop 守护进程在本次排查中途宕机，需重启 Docker Desktop 服务/应用后才能继续重建 backend 镜像。
- 本次未真正重建 backend 镜像（守护进程宕机）。待 Docker 恢复后执行 `docker compose up -d --build backend`，再 `docker compose up -d` 拉起全栈。
